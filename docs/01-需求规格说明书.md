# 广西职业师范学院罗文校区图书馆自习室预约系统 — 需求规格说明书

> 版本：V1.0（设计待确认稿）
> 项目性质：本科毕业设计实验项目
> 适用范围：广西职业师范学院罗文校区图书馆（单栋楼宇，1-5 层）

---

## 第一部分 项目概述（对应论文第一章 绪论）

### 1.1 项目背景

广西职业师范学院罗文校区图书馆共 5 层，均设有开放自习区域。当前采用线下先到先得的座位管理模式，存在以下痛点：

- 占座、抢座乱象普遍，座位资源分配不公平，学生矛盾频发；
- 5 层自习室空位信息不透明，学生无法提前获知空位，往返找座时间成本高；
- 爽约、占座等违规行为缺乏约束机制，难追溯、难处罚；
- 图书馆管理员人工管理效率低，缺少数据化运营支撑，无法针对性优化座位配置。

本系统实现图书馆自习室座位的线上预约与数字化管理，目标是：提升座位利用率与学生自习体验、建立信用约束机制、降低人工管理成本。

### 1.2 服务对象

| 角色 | 说明 |
|---|---|
| 在校学生 | 系统核心使用者，注册账号、浏览自习室、预约座位、签到签退、查看信用分 |
| 图书馆管理员 | 负责自习室与座位维护、预约订单运营、违规日常处理、公告发布、数据统计 |
| 超级管理员 | 负责系统配置、全量用户与角色管理、信用分调整、禁用解除、操作日志审计 |

### 1.3 项目范围与边界

**本期实现：**

1. 图书馆 1-5 层所有自习室座位的线上预约管理；
2. 用户注册登录、座位预约、手动签到签退全流程；
3. 信用积分机制与违规禁用、自动解禁、手动解禁功能；
4. 后台自习室、座位、预约订单、用户、违规全量管理；
5. 基础运营数据统计（ECharts 图表 + Excel 导出）与系统公告发布。

**本期不实现（边界）：**

- 不开发微信小程序、移动端 APP，仅提供 Web 网页端；
- 不接入校园一卡通、人脸闸机等硬件设备，采用独立账号体系；
- 不实现任何付费功能，所有自习室座位免费使用；
- 不支持多校区、多楼栋管理，仅覆盖罗文校区图书馆单栋楼宇；
- 不实现扫码签到、定位签到，仅支持页面内手动点击签到。

### 1.4 技术方案概述

前后端分离 B/S 架构：Vue3 + Element Plus + Pinia（前端），Spring Boot 3.2.x + MyBatis-Plus + MySQL 8.0 + JWT（后端），本地单体部署（前端 5173 / 后端 8080 / MySQL 3306）。详见《02-技术架构与目录结构设计》。

### 2.2 用户端功能需求

#### 2.2.1 账号与个人中心

- **注册**：学号（唯一校验）、姓名、密码、手机号；密码加密存储。
- **登录**：学号 + 密码，支持"记住密码"（本地存储学号，密码不持久化明文）。
- **找回密码**：手机号 + 验证码重置密码（开发环境使用模拟验证码：后台生成 6 位数字码，有效期 5 分钟，接口返回中附带以便演示，不接入真实短信通道）。
- **个人信息**：修改头像、昵称、手机号、登录密码。
- **我的信用**：当前信用分、扣分记录、禁用状态与解禁时间。
- **消息通知**：预约提醒、违规通知、系统公告（站内信列表 + 未读数）。

#### 2.2.2 自习室浏览

- 自习室列表：按楼层（1F-5F）Tab 切换，卡片展示名称、楼层、座位总数、实时空余数、开放时间、类型标签；
- 筛选：楼层、座位类型（靠窗 / 带插座 / 静音区）、关键词搜索；
- 自习室详情：座位平面图（按 position_x / position_y 坐标渲染），颜色区分状态：
  - 绿色 = 空闲，灰色 = 已预约/不可用，蓝色 = 使用中（本人座位高亮描边）；
- 座位详情：点击座位弹窗展示属性与当日各时段预约情况。

#### 2.2.3 预约管理（核心业务）

- **预约提交**：选择座位 + 日期（限今天/明天）+ 时间段（30 分钟粒度，起始对齐 :00 / :30）。
- **预约规则校验**（全部在服务端校验，前端仅做提示）：
  1. 用户账号正常、未处于预约禁用期；
  2. 预约时段在自习室开放时间内；
  3. 该座位在所选时段无冲突订单（冲突校验，见 2.4.1）；
  4. 同一用户同一时段不可重复预约（跨自习室也拦截）；
  5. 每日最多预约 2 单（按 booking_date 统计，不含已取消）；
  6. 单次时长 30 分钟 ~ 4 小时；
  7. 预约开始时间不得早于当前时间。
- **取消**：预约开始时间前可取消，开始后不可取消；取消即释放座位。
- **签到**：预约开始时间起 30 分钟内可点击签到（如 09:00 的预约，09:00–09:30 可签到）；签到后订单进入"进行中"。
- **签退**：进行中可签退，即时释放座位，订单置为"已完成"。
- **续时**：进行中可延长 end_time（30 分钟粒度，总长不超 4 小时上限的剩余额度），需校验延长时段座位空闲。

#### 2.2.4 记录查询

- 全部预约记录：时间倒序，状态标签（待签到 / 进行中 / 已完成 / 已取消 / 已爽约）；
- 违规记录：本人违规列表（类型、原因、扣分、时间）；
- 收藏：收藏/取消收藏自习室，收藏列表一键进入详情。

#### 2.2.5 公告与帮助

- 公告列表（置顶优先）、公告详情；首页公告轮播。
- 帮助中心：预约规则、信用分规则、常见问题（静态内容页）。

### 2.3 管理端功能需求

#### 2.3.1 数据看板（所有管理员）

今日预约数 / 签到率 / 爽约数 / 当前在使用座位数；近 7 天预约趋势图；各楼层利用率柱状图。

#### 2.3.2 基础数据管理（所有管理员）

- 楼层管理：1-5 层信息维护（只读为主，名称/说明可编辑）；
- 自习室管理：增删改查，设置名称、楼层、开放/关闭时间、类型、简介、上下架；
- 座位管理：按"行 × 列"批量生成座位（自动编号、自动坐标），单个编辑编号/类型/插座/坐标/可用状态；
- 公告管理：发布、编辑、删除、置顶、上下架。

#### 2.3.3 预约运营（所有管理员）

- 订单管理：全量订单分页查询，按用户、自习室、楼层、日期、状态组合筛选；
- 订单操作：强制取消（需填备注）、修改预约时间、添加备注；强制取消给用户发送站内通知。

#### 2.3.4 违规管理（所有管理员）

- 违规记录列表（自动爽约 + 手动添加）；
- 手动添加违规：选择用户、类型（爽约/占座/其他）、扣分值，同步扣减信用分并触发禁用判定；
- 撤销违规：恢复对应扣分，若用户因此违规被禁用且当前分 ≥ 60，联动解除禁用。

#### 2.3.5 信用与禁用管理（超级管理员专属）

- 禁用用户列表：禁用原因、开始/解禁时间、当前信用分；
- 手动提前解禁：解除禁用并将信用分恢复至 60 分；
- 信用分调整：手动加/减分（填原因），减分后低于 60 触发禁用判定。

#### 2.3.6 系统管理（超级管理员专属）

- 用户管理：查询、新增、编辑、删除（逻辑删）、禁用账号（不可登录）、重置密码；
- 角色管理：角色列表、新增编辑、分配菜单权限；
- 系统设置：预约规则与信用规则参数化配置（见 2.4.4 配置项表）；
- 操作日志：操作人、模块、内容、IP、时间，支持筛选查询。

#### 2.3.7 数据统计（所有管理员）

- 座位利用率：按日/周/月，按楼层、自习室维度统计上座率（公式：实际使用时长 ÷ 开放时长）；
- 热门时段：一天中各时段预约量分布热力/柱状图；
- 用户行为：活跃用户数、人均预约时长、违规率、禁用率；
- 导出：统计报表导出 Excel（EasyExcel / Hutool）。

### 2.4 核心业务规则与实现逻辑

#### 2.4.1 预约冲突校验

同一座位同一天的有效订单（status ∈ {0 待签到, 1 进行中}）时间段不得重叠。

重叠判定（区间相交）：

```text
存在冲突 ⟺ 已有订单.start_time < 新订单.end_time
           AND 已有订单.end_time > 新订单.start_time
```

SQL 逻辑：

```sql
SELECT COUNT(*) FROM booking_order
WHERE seat_id = #{seatId}
  AND booking_date = #{date}
  AND status IN (0, 1)
  AND start_time < #{endTime}
  AND end_time   > #{startTime};
-- count > 0 即冲突，拒绝预约
```

实现要点：
- 校验与写入在同一事务内；并发场景使用 `SELECT ... FOR UPDATE`（按 seat_id + booking_date 加锁行）或数据库唯一约束兜底，防止 50 人并发下同座位同时段重复下单；
- "同一用户同一时段不可重复预约"用同样区间相交逻辑，把 seat_id 条件换成 user_id；
- 前端提交按钮防重复点击 + 后端幂等（事务内复查冲突）。

#### 2.4.2 签到 / 爽约判定

- 签到窗口：`[start_time, start_time + 30分钟]`。窗口内点击签到 → status: 0→1，记录 checkin_time。
- 爽约判定（定时任务）：每分钟扫描一次：

```text
status = 0（待签到）AND booking_date = 今天
AND NOW() > booking_date + start_time + 30分钟
  → status = 4（已爽约），释放座位
  → 生成 violation_record（type=爽约, deduct=10, create_by=系统）
  → credit_score -= 10，进入 2.4.3 禁用判定
  → 推送站内通知
```

> 窗口分钟数、扣分值均走 sys_config 配置（默认 30 分钟 / 10 分）。

#### 2.4.3 信用分扣减与禁用 / 解禁

流转规则：

```text
初始 credit_score = 100
每次违规（爽约 / 管理员手动）→ credit_score -= deduct_score
禁用判定：任何一次扣分后 credit_score < 60
  → is_disabled = 1
  → disable_end_time = NOW() + 7天
  → 生成 disable_record（含原因、起止时间）
  → 该用户提交预约时拦截，返回禁用状态与解禁时间
自动解禁（定时任务，每分钟）：
  disable_record.is_lifted = 0 AND end_time <= NOW()
  → is_lifted = 1（lift_by = 系统），sys_user.is_disabled = 0
  → credit_score 恢复至 60
手动解禁（超管）：
  同上，lift_by = 管理员ID，同步恢复信用分至 60
手动调整信用分（超管）：
  加分/减分留痕（violation_record 或专用流水），减分后 < 60 触发禁用判定
撤销违规：
  恢复该违规扣除的分数；若当前无其他生效禁用原因且分数 ≥ 60 → 联动解禁
```

实现要点：扣分、生成违规记录、禁用判定、写禁用记录在同一事务；所有变更写操作日志。

#### 2.4.5 定时任务清单（Spring @Scheduled）

| 任务 | 频率 | 逻辑 |
|---|---|---|
| 爽约扫描 | 每 1 分钟 | 超时未签到订单 → 爽约 + 扣分 + 禁用判定（2.4.2/2.4.3） |

## 第三部分 系统设计（对应论文第四章）

### 3.1 总体架构

B/S 前后端分离，四层划分：

```text
┌────────────────────────────────────────────┐
│ 表现层  Vue3 SPA（用户端 /admin 管理端双入口） │
├────────────────────────────────────────────┤
│ 接口层  Spring MVC Controller               │
│         JWT 拦截器 · 参数校验 · 统一响应     │
├────────────────────────────────────────────┤
│ 业务层  Service（预约/信用/定时任务核心规则） │
├────────────────────────────────────────────┤
│ 数据层  MyBatis-Plus Mapper → MySQL 8.0    │
└────────────────────────────────────────────┘
```

### 3.2 数据库设计（ER 与表结构）

**核心关联**：角色 1—N 用户；楼层 1—N 自习室；自习室 1—N 座位；用户 1—N 订单/违规/禁用记录/收藏；座位 1—N 订单。

共 12 张表（需求文档 10 张 + 补充 2 张）：

| 表 | 说明 |
|---|---|
| sys_user | 用户（学号唯一、信用分、禁用状态） |
| sys_role | 角色（student / librarian / super_admin） |
| library_floor | 楼层（1-5F） |
| study_room | 自习室（楼层、开放时间、类型） |
| study_seat | 座位（编号、坐标、类型、插座、状态） |
| booking_order | 预约订单（状态机：0待签到→1进行中→2已完成 / 3已取消 / 4已爽约） |
| violation_record | 违规记录（类型、扣分、操作人） |
| disable_record | 禁用记录（起止时间、解除人） |
| sys_notice | 公告（置顶、上下架） |

| sys_message（补充） | 站内消息（预约提醒/违规通知/公告） |
| sys_operation_log（补充） | 操作日志 |

> 字段明细以需求文档板块 7 为准；补充表字段在《02-技术架构与目录结构设计》数据库脚本章节给出完整 DDL。

**索引设计**：
- booking_order：(seat_id, booking_date, status)、(user_id, booking_date)、(status, booking_date)——支撑冲突校验与定时扫描；
- sys_user：username 唯一索引；
- violation_record / disable_record / user_favorite：(user_id)；
- sys_message：(user_id, is_read)。

**卡通实现规范**：组件统一 12px 圆角；柔和淡蓝阴影（如 `0 4px 16px rgba(74,144,226,.12)`，禁生硬黑影）；线性圆角卡通图标（书本、座位、图书馆等校园元素）；登录页、空状态页、404 页配套「图书馆、书本、座位」主题简约卡通插画（蓝白主调、与 #4A90E2 同色系）；按钮 hover 轻微上浮动效（translateY(-2px) + 阴影加深），页面切换淡入过渡，交互流畅不花哨，避免 Element Plus 默认商务感。

**布局字体**：系统无衬线字体；标题 16–20px、正文 14px；8px 栅格（间距 8/16/24）；用户端 = 顶部导航 + 内容区，管理端 = 左侧菜单 + 内容区。

### 3.5 验收标准摘要（对应论文第五章）

- 功能：注册唯一校验；预约冲突/禁用拦截；签到签退状态流转正确；爽约自动扣 10 分、<60 自动禁用 7 天、到期自动解禁恢复 60 分；管理端增删改查前台联动；多角色权限隔离生效；统计与业务数据一致且可导出。
- 非功能：首屏 ≤3s、预约 ≤1s、30 并发无报错；三浏览器兼容；密码密文、未登录 401；连续运行 24h 无宕机、定时任务准确。
