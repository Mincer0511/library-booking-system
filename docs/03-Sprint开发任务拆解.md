# Sprint 开发任务拆解（3 个里程碑版本）

> 版本：V1.0（设计待确认稿）
> 原则：每个 Sprint 结束产出一个**可独立运行、可演示**的版本，对应实验要求的「每周可运行版本」。
> 版本路线：V1.0 基础可用 → V2.0 核心业务 → **V2.1 需求变更**（Sprint 2 后插入，见「需求变更插入点」）→ V3.0 完整交付。

---

## 里程碑总览

| 版本 | 目标 | 核心交付 | 可演示场景 |
|---|---|---|---|
| **V1.0** 基础可用 | 工程跑通 + 用户体系 + 座位浏览 + 基础预约 | 前后端脚手架、JWT 登录注册、自习室/座位展示、预约与取消 | 注册登录 → 浏览 5 层自习室 → 选座预约 → 取消预约 |
| **V2.0** 核心业务 | 预约全生命周期 + 信用分体系 | 签到/签退/续时、爽约判定、信用分扣减、禁用/自动解禁、我的信用/违规/收藏/公告 | 签到签退 → 模拟爽约扣分 → 触发禁用 → 自动/手动解禁 |
| **V2.1** 需求变更 | 模拟甲方需求变更（Sprint 2 完成后插入） | 预约到期前 10 分钟站内信提醒 | 临期订单收到提醒消息 |
| **V3.0** 完整交付 | 管理端全量 + 数据统计 + 收尾 | 后台 13 个页面、数据统计 ECharts + Excel 导出、系统设置、操作日志、找回密码、测试与文档 | 管理员全量运营操作 + 数据看板/统计 + 多角色权限对比演示 |

## 需求变更插入点（V2.1，实验硬性要求）

> 实验明确要求「中途处理一次模拟甲方需求变更」。Sprint 2 完成、Sprint 3 开始前，插入一次模拟甲方需求变更，形成 V2.1 版本，并保留完整修改记录（变更说明、代码 diff、Git 提交、迭代日志），直接对应实验评分点。

**变更单**

| 项 | 内容 |
|---|---|
| 变更编号 | CR-001 |
| 提出方 | 模拟甲方（图书馆） |
| 变更内容 | 增加「预约到期前 10 分钟站内信提醒」：进行中订单在 end_time 前 10 分钟向用户推送站内信，提醒及时签退或续时 |
| 变更版本 | V2.0 → V2.1 |
| 影响范围 | 后端：BookingSchedule 新增临期提醒扫描任务（复用 sys_message）；前端：消息中心提醒类型展示 |
| 具体改动 | ① BookingSchedule 增加 `scanExpiringSoon()`：每分钟扫描 status=1 且未发送过临期提醒、now ∈ [end-12min, end-8min] 的订单，写 sys_message；② booking_order 增加 `expire_notified` 标记位（ALTER TABLE 留痕）；③ 消息中心增加「临期提醒」类型图标与文案 |
| 修改记录 | 变更说明 + ALTER 语句 + 代码 diff + Git 提交（`feat/cr001: 增加预约到期前10分钟站内信提醒`），归档至迭代日志 |

## 任务依赖与关键路径

```text
Sprint 1: B1-1~B1-5(骨架) → B1-6(认证) → B1-7(自习室) → B1-8(预约)
           前端 F1-1~F1-4 与后端并行，F1-5 起联调
Sprint 2: B2-1(签到签退) → B2-2(信用核心) → B2-3(定时任务) → B2-10(全链路测试)
           依赖 Sprint 1 的订单模型与状态机
Sprint 3: B2-9(角色权限) → 管理端各模块（并行度高）→ B3-9/10(统计) → B3-11(加固)
           统计模块依赖完整业务数据，安排在最后
```

**风险与应对**

| 风险 | 应对 |
|---|---|
| 并发预约重复下单 | 事务 + 行锁（FOR UPDATE）+ 索引兜底，Sprint 3 压测验证 |
| 定时任务时间不准 | 扫描条件用数据库 NOW() 口径统一；测试提供"时间偏移"调试参数 |
| 座位平面图渲染性能 | 按自习室分页加载，坐标数据一次性拉取，前端局部渲染 |
| 管理端工作集中 Sprint 3 | Sprint 2 已完成角色权限基础（B2-9），Sprint 3 各管理模块可并行开发 |

## Git 提交规范（原创性证据）

实验要求提交「Git 历史」作为原创性证据，全程按以下规范提交，最终 Git 记录可直接作为实验材料：

**提交格式**：`类型/模块: 内容描述`

| 类型 | 用途 | 示例 |
|---|---|---|
| feat | 新功能 | `feat/sprint1: 实现用户注册登录功能` |
| fix | 缺陷修复 | `fix: 修复预约冲突校验bug` |
| feat/cr001 | 需求变更 CR-001 | `feat/cr001: 增加预约到期前10分钟站内信提醒` |
| refactor | 重构 | `refactor: 抽取信用分扣分公共方法` |
| docs | 文档 | `docs: 补充需求规格说明书界面规范` |
| test | 测试 | `test/sprint2: 爽约扣分全链路测试用例` |
| chore | 工程杂项 | `chore: 初始化前后端工程骨架` |

**提交要求**：每个 Sprint 任务编号（如 B1-6、F2-3）对应至少一次独立提交；需求变更、缺陷修复必须单独提交；每完成一个 Sprint 打 Tag（`v1.0` / `v2.0` / `v2.1` / `v3.0`），保证 Git 历史与迭代日志一一对应。
