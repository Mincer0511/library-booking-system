## 需求变更 CR-001（V2.0 → V2.1）

**变更单**：见《03-Sprint开发任务拆解.md》「需求变更插入点」章节（变更编号 CR-001，提出方：模拟甲方图书馆）。

**变更内容**：进行中订单在结束前约 10 分钟向用户推送站内信，提醒及时签退或续时。

### 数据库变更（ALTER 留痕）

```sql
ALTER TABLE booking_order ADD COLUMN expire_notified TINYINT NOT NULL DEFAULT 0
  COMMENT '是否已发送临期提醒：0否 1是（CR-001）';
```

同步更新建表脚本 `library-server/src/main/resources/sql/schema.sql`（新环境建库直接含该列，无需再执行 ALTER）。

### 代码改动清单

| 文件 | 改动说明 |
|---|---|
| `library-server/.../entity/BookingOrder.java` | 新增 `expireNotified` 字段（临期提醒标记位） |
| `library-server/.../schedule/BookingSchedule.java` | 新增 `scanExpiringSoon()` 定时任务：每 1 分钟扫描 status=1（进行中）且未提醒、now ∈ [end-12min, end-8min] 的订单，写 sys_message（type=提醒）并置 expire_notified=1 |
| `library-server/.../resources/sql/schema.sql` | booking_order 建表语句增加 expire_notified 列 |
| `library-web/src/views/my/MessageView.vue` | 消息中心新增「提醒」类型展示：⏰ 图标 / 橙色图标底 / warning 标签 |

**设计说明**：扫描窗口宽度 4 分钟大于任务周期 1 分钟，配合 expire_notified 标记位，保证每个订单恰好提醒一次且服务重启不重复推送。

### 验证记录

1. 后端打包含集成测试：`Tests run: 4, Failures: 0, Errors: 0`，既有信用分全链路不受影响；
2. 实测临期提醒：将测试订单置为进行中、end_time 设为当前时间 +10 分钟 → 新服务启动后首次扫描（20 秒）即命中：`expire_notified 0→1`，写入站内信「预约即将到期」（type=提醒，未读）；
3. 幂等验证：再等待一个扫描周期，该用户「预约即将到期」消息数保持 1 条，未重复推送；
4. 前端构建通过；浏览器实测消息中心正确展示 ⏰「提醒」类型消息（图标 / 标签 / 展开正文），既有类型展示不受影响。
